# R1 temporary living-ragdoll API (experimental v1)

Purpose: expose a reversible physical state for living stalker NPCs and the actor.
The engine owns body creation, control/AI suspension, item-pickup guards, recovery
and lifetime cleanup. Addons own triggers, probabilities, durations, camera choice,
injury/medical/loot rules and persistence. This source change contains no Dynamic
Reactions payload, DLL loader, offsets, extra models, MCM or automatic knockout rules.

Built on ordinary x64 DX11 Modded Exes October source
`c57fe5b9fab4fe0506659db03137c52d2500eb2f`. Other renderers/AVX/MT and arbitrary
modpacks need separate validation; compatibility is not inferred from compilation.

## Lua methods on `game_object`

| Method | Result |
| --- | --- |
| `object:ragdoll_status()` | `available`, `active`, `not_alive`, `physics_processing`, `physics_frozen`, `busy`, `in_holder`, `unsupported_model`, or `unsupported_type` |
| `object:ragdoll_start()` | Nonzero exclusive request token; zero means refused without starting a request |
| `object:ragdoll_active()` | Whether the temporary state currently exists |
| `object:ragdoll_stop(token)` | True on completed recovery; false for a wrong/expired token, death, absent body, physics processing or blocked recovery |

Tokens are generated by the engine across object lifetimes. A second start does not
replace an active request. Keep the returned token only for the current object and
runtime; never save it or re-resolve a stale object by numeric ID alone. The native
state is stored on the character physics support, not in a global object-ID table.

```lua
local token = npc:ragdoll_start()
if token ~= 0 then
    local shell = npc:get_physics_shell()
    shell:set_linear_vel(vector():set(2, 1, 0))
    -- Keep npc identity/token in this addon's own runtime record.
    -- Later, from a safe game update, request npc:ragdoll_stop(token).
end
```

The same methods work on `db.actor`. Use the existing physics-shell bindings for
velocity and other supported physical controls. Start/stop refuse calls during
physics processing/frozen worlds; recovery also refuses a frozen body. Queue the gameplay request until a safe update instead of
calling from a collision callback. A successful stop restores the living movement
controller and animation callbacks. A blocked recovery leaves the same request
active so its owner can retry; it is not reported as success.

## Native behavior

- Living health/death identity is preserved; no fake death, invulnerability or
  resurrection is used. The existing engine ragdoll skeleton is reused.
- Stalker AI, animation and object-handler updates are suspended while the body
  is active. Old position samples/path state are refreshed on recovery.
- Actor movement, use/pickup and weapon input are blocked; camera viewing can
  remain addon-controlled. The small example selects third person.
- The common inventory `CanTakeItem` gate rejects items for a ragdolled owner,
  including ownership events already queued before the transition. Existing
  rejection handling maintains server ownership. Ordinary magazine weapon fire
  is stopped/guarded as part of temporary control suspension.
- A fatal event retains the existing shell as a corpse and expires its token.
  Destroying an object clears its runtime state.
- Save packets omit transient tokens and corpse bone state for living ragdolls.
  Loading restores ordinary living characters; addons may rebuild their gameplay
  state separately. Saving/reloading requires acceptance against the actual build.

Only actor/stalker character types with a suitable physical skeleton are accepted.
Mounted characters, animated movement controllers, existing bodies and unavailable
movement controllers are refused. This is not a general mutant/multiplayer API.
Addons that replace low-level character state still require compatibility checks.

## Separate example and references

The separate [R1 Ragdoll Demo branch](https://github.com/noname-r1nk1/R1_XREAL_xray-monolith/tree/R1_ragdoll_demo/examples/R1_Ragdoll_Demo)
