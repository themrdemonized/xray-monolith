# R1 Multi View — ветка интеграции обычного DX11

Основа: Modded Exes 2026.10.11,
`c57fe5b9fab4fe0506659db03137c52d2500eb2f`. Ветка содержит только исходники
движка и документацию. Lua/MCM аддонов, модели оружия, текстуры двери, события
аномалий, EXE/PDB и тестовые сейвы поставляются отдельно. Новые сторонние
библиотеки не добавлены: D3DCompiler уже используется рендерером, DirectXMath
и WRL входят в SDK.

В движке оставлены восемь независимых камер, вывод в текстуру/экранный
прямоугольник/поверхность мира, преобразование камеры и плоскость отсечения,
настоящий масштаб буферов, качество и интервал обновления. Три ограниченных
набора промежуточных буферов переиспользуются видами одного разрешения.
Невидимые мировые поверхности пропускаются. Замещающий основной вид позволяет
SBS обходиться двумя мировыми проходами. Повторных тиков актёра/Lua на каждый
вид нет; камеры берут одно состояние игрового кадра.

Выбор оружия, IPD, отражение относительно плоскости зеркала, геометрия и
открывание двери, события, настройки MCM и сохранение состояния остаются в
аддонах. Эти определения и ресурсы в EXE не встраиваются.

## API v1

Функции: `level.r1_view_api_version()`, `r1_view_set(id, parameters)`,
`r1_view_clear(id)`, `r1_view_status(id)`, `r1_view_geometry(id, geometry)`.
ID: 0–7. Размеры: 64–4096. Интервал: 1–120 кадров. Качество: 0–2.
Без обновления описание истекает через 1500 мс. Аддоны должны согласовывать
владение слотами и очищать свои виды при загрузке/выходе/смене уровня.

```lua
level.r1_view_set(5, {
    relative=true, width=640, height=360, fov=20,
    hud=false, quality=1, interval=1, output=1,
    rect_x=0.75, rect_y=0.02, rect_w=0.24, rect_h=0.25
})
-- Обновляйте описание, пока камера активна.
level.r1_view_clear(5)
```

`relative=false` использует position/direction/up. `offset` задаёт локальное
смещение, `camera_transform` — аффинную матрицу. FOV горизонтальный, aspect
равен высоте/ширине. `clip` и plane_x/y/z/d задают наклонную ближнюю плоскость.
`flip_x` разворачивает выборку изображения в композиторе; собственному шейдеру
сырой текстуры требуется развернуть U самостоятельно. `hud` управляет оружейным
HUD прохода, `actor_body` — телом актёра. output: 0 текстура, 1 экран, 2 мир.
`primary` замещает основной мировой проход и требует output=1, interval=1.
quad_position/right/up задают центр и полуразмеры поверхности.

Имя текстуры: `$user$r1mv_<id>`. Геометрия — треугольники, до 256 вершин,
число кратно трём. Вершина: `{position=vector(), u=0, v=0, material=0}`.
Материал 0 — вид камеры, 1/2 — texture1/texture2. Освещение этих материалов
сейчас упрощено до unlit. Обычное PiP сохраняет HUD основного экрана; при
замещении основного вида интерфейс копируется в экранные слоты с hud=true.

Статус: valid/ready/error, реальные width/height, frame, renders/draws,
render_ms/total_ms. Время — CPU с целой миллисекундной точностью, не GPU.
Ошибки: -2 HDR/MSAA, -3 буферы, -4 сдвиг игрового кадра, -5 композитор.

## Проверки и границы

Сборка: x64 DX11 без AVX, VS2022/MSVC14.44, SDK10.0.26100.0. Отдельные SBS,
ACOG ADS, открывание исходной двери и зеркало проверены в изолированной игре.
Совместный сценарий проверяет ACOG + дверь + зеркало, независимые отключение
и масштаб, затем обычное PiP-окно с обеими мировыми поверхностями. Хэши,
свежие логи, скриншоты и замер размера EXE сохранены в локальной передаче.

HDR/MSAA, MT и другие рендереры не приняты. У вторичных камер отключена
временная история TAA/SSR. Вложенные зеркала/порталы не рендерятся: мировые
поверхности R1 выводятся в основной вид. SBS совместно с дополнительными
видами, физические очки, полный проход/возврат через дверь, длительная игра
и произвольные модпаки не приняты. Это кандидат на интеграцию исходников;
слияние в upstream и общий стабильный релиз не заявлены.

Трава вторичных видов использует существующие списки видимости/кэш основной
камеры. За пределами этого кэша в удалённых видах трава может отсутствовать;
отдельный стриминг травы удалённых камер в минимальную интеграцию не входит.
