## Early next-work notes (historical)

`EntityRegistry.h` implements bounded session identities and worker/level/native-object mappings without engine pointers. Bindings increment generation on recreation, preserve identity while inactive, reject duplicate engine keys and stale destroys, and invalidate only the specified worker/level on unload. IDs are not reused after erasure. Protocol level and worker IDs are nonzero logical IDs; a future engine adapter must map native graph level IDs (including zero) into that namespace. `EntityTests.cpp` covers isolation and lifecycle cases. Engine spawn/despawn hooks remain pending.

Actor snapshot wire data and interpolation are now implemented in `ActorSnapshot.h`, but have no engine adapter yet. The snapshot includes network entity ID, binding generation, level ID, tick, server time, position, velocity, rotation, movement flags, and stance. Explicit little-endian IEEE754 encoding rejects truncation/trailing bytes, invalid identity/stance, and nonfinite values. The 32-sample buffer rejects other levels/generations and stale ticks/timestamps; rebinding clears old samples. Interpolation uses a configurable 100 ms default delay, shortest-angle rotation, and holds the newest sample rather than extrapolating indefinitely. `SnapshotTests.cpp` passes alongside the protocol/session suites with warnings as errors. This does not prove remote engine actors, movement authority, prediction, or gameplay replication.

Implement the real transport adapter and session message dispatcher, roster broadcasting, handshake timeout, and disconnect notification. Then integrate opt-in engine commands/update dispatch. Follow the full implementation plan; manual gameplay baseline and the unrecovered original design tail remain outstanding.

## Session primitives verified

`ClientPump.h` provides an owner-thread client handshake/roster dispatcher with a 10-second handshake timeout and a 32-message per-update processing bound. `Roster.h` now serializes up to four public participant entries, excluding reconnect tokens and connection handles. Decoding rejects duplicate identities, invalid flags, missing/disconnected host, invalid count, truncation, and trailing data. Client roster application is session-scoped, requires its connected participant, and rejects stale revisions. Roster tests pass with both existing suites. Network broadcasting is still pending.

`Session.h` adds host admission and a client state machine, versioned hello/welcome codecs, game/mod build compatibility, stable character/player/session identity, a four-participant registry, explicit duplicate rejection, disconnected character retention, token-based reconnect with increasing actor-binding generation, and explicit release after checkpoint/export.
