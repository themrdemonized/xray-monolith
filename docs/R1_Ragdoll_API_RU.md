# R1 API временного регдола живых персонажей (экспериментальный v1)

Движок предоставляет обратимое физическое падение живого NPC-сталкера и игрока.
Создание тела, приостановка управления, запрет подбора, восстановление и очистка
принадлежат движку. Условия включения, вероятность, длительность, камера, травмы,
лечение, лут и сохранение игровой логики принадлежат аддону. В EXE не включены
Dynamic Reactions, DLL-загрузчик, адреса функций, новые модели или правила нокаута.

База: обычные Modded Exes октября, исходник
`c57fe5b9fab4fe0506659db03137c52d2500eb2f`; целевая сборка DX11 x64. AVX, другие
рендереры, MT и произвольные сборки модов требуют отдельных проверок.

| Lua-метод `game_object` | Результат |
| --- | --- |
| `object:ragdoll_status()` | `available`, `active`, `not_alive`, `physics_processing`, `busy`, `in_holder`, `unsupported_model` или `unsupported_type` |
| `object:ragdoll_start()` | Уникальный ненулевой токен запроса; 0 означает отказ |
| `object:ragdoll_active()` | Наличие временного состояния |
| `object:ragdoll_stop(token)` | true только после восстановления; false при чужом/старом токене, смерти, отсутствии тела, обработке физики или занятом месте |

Повторный запуск не заменяет чужой запрос. Токен создаётся движком, а состояние
хранится на самом персонаже. Храните токен только в памяти текущего игрового сеанса
вместе с проверяемой идентичностью объекта; не сохраняйте его и не считайте ID
постоянным идентификатором после удаления персонажа.

```lua
local token = npc:ragdoll_start()
if token ~= 0 then
    npc:get_physics_shell():set_linear_vel(vector():set(2, 1, 0))
    -- Запомнить объект и токен в памяти аддона.
    -- Позже, в безопасном обновлении: npc:ragdoll_stop(token).
end
```

Для игрока используются те же методы `db.actor`. Скорости и другие физические
воздействия задаются существующим API physical shell. Из физического collision
callback запускать/завершать нельзя: перенесите запрос на безопасное обновление.
Если восстановление заблокировано, тело и токен сохраняются для повторной попытки.

Здоровье и реальная смерть сохраняют обычный смысл: нет фиктивного убийства,
бессмертия или воскрешения. NPC во время падения не исполняет AI/анимации/управление
оружием. У игрока блокируются движение, действия с предметами и оружейный ввод.
Общий `CanTakeItem` отвергает подбор для лежащего владельца, включая уже поставленные
в очередь события владения. Штатный путь отказа исправляет серверное владение.

Смерть использует уже существующее тело и завершает запрос. Удаление очищает
временное состояние. В сохранение не попадают токены и физические кости «трупа»
живого персонажа: после загрузки он возвращается к обычному состоянию. Проверка
сохранений должна относиться к конкретной сборке, а не только к чтению кода.

Принимаются только игрок/NPC-сталкер с подходящим физическим скелетом. Транспорт,
управление движением анимацией, существующее физическое тело и недоступный контроллер
движения означают отказ. Поддержка мутантов и сетевой игры не заявлена.

Отдельный `R1_Ragdoll_Demo` показывает вызовы: F6 — NPC под прицелом, F7 — игрок,
F8 — завершить свои падения; необязательный MCM задаёт длительность и толчок.
Пример и тесты не запускаются автоматически при установке изменений движка.
